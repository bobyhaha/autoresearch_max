The two conventions disagree in **opposite directions** and this is the whole point:
- **Spectral (Modula) rule** `(A/B)**0.5`: mlp.c_proj 1.0 → **0.5**. This is the brief's "stops receiving 2x the prescribed rate".
- **RMS-matching rule** `(max/min)**0.5`: an orthogonalized A×B matrix has element RMS `1/sqrt(max(A,B))`, so per-element step = lr·factor/sqrt(max(A,B)). Today that is 1.77e-3 for (512,512), 1.77e-3 for c_fc, and **0.88e-3 for mlp.c_proj — already half**. This rule sends c_proj 1.0 → **2.0**.

So the "correction" halves an LR that a second, equally standard normalization says is already halved. My recommendation: run **both** one-line variants as a bracket around the status quo. Same cost (zero), and the pair discriminates two theories instead of guessing a sign. mlp.c_proj is 8.4M of 25.2M Muon params (33%) and is zero-initialized, so its LR is high-leverage.

**RISK: low, with one blocker.** A new cfg key is an unknown key: `direction.py:74 KNOWN_KEYS` → `is_platform` fails safe, and per L012 the host's `direction.py` must be re-shipped and md5-verified before the first launch.
