## pipeline_integrity (pipe-int-1)

**SEVERITY 1 — a crashed run across a dispatcher restart is invisible forever, and it wedges its whole wave.** The recovery paths compose into a hole. `recover_orphans()` writes a record only when the log contains a metric: `if "val_bpb:" not in txt: continue` (host/dispatch.py:365). `release_stranded_claims()` frees a claim only when there is *no* work dir: `if (ROOT / "work" / c.name).is_dir(): continue` (dispatch.py:399). `adopt_running()` skips a dead pid and defers to recover_orphans (dispatch.py:438-455). So a trainer that crashed before printing `val_bpb` (OOM, SIGKILL, import error) while the dispatcher was down leaves: a claim, a work dir, an out.log with no metric — no path writes a result, no path releases the claim. The entry is skipped by `runnable()` forever, AND `tombstone_split_wave()` treats the zombie claim as in-flight — `if not done or not stranded or inflight: return False` (dispatch.py:230) — so its finished wave-mates are never reconciled either. This is exactly the "treatments stranded when their wave-mates finished" failure class, still open. If the same crash happens while the dispatcher is *alive*, the poll loop writes `ok:false` correctly (dispatch.py:520-538); only the restart window is unguarded, and restarts are routine here (that is why adoption exists).

**SEVERITY 2 — co-tenancy amnesia across restart.** The `cotenant` flag and the quarantine dict live only in process memory. `adopt_running()` re-attaches every job with `"cotenant": False` (dispatch.py:465), and a run recovered by `recover_orphans()` gets a record with no `cotenant_detected` field at all and `ok: true` (dispatch.py:369-377). A foreign tenant that landed before the restart is forgotten, and the invalidated run is recorded valid. The memory's "co-tenancy kill" loss path is closed only while one dispatcher process survives the whole run.

**SEVERITY 3 — a policy block arising after queueing wedges a wave with no exit.** `runnable()` drops policy-blocked entries (`if blocked_reason(item["cfg"], state)`, dispatch.py:150), but `wave_sizes()` counts them — it filters only cutoff-frozen non-controls (dispatch.py:185-188). The host recomputes `axis_state` from fresh results every poll, so an axis can go dry *between* the local door check (queue_from_round.py, run against results up to ~20 min stale) and launch. Result: runnable members < queued size → `broken`; `tombstone_split_wave` requires a finished member (`if not done...`, dispatch.py:230), there is none, so the wave logs `WAVE SPLIT` (dispatch.py:298) every pass, indefinitely — controls held hostage, treatment never tombstoned, nothing recorded. The cutoff-frozen case got the `held` treatment (dispatch.py:279-290, L022/L023); the policy-blocked case did not.

**SEVERITY 4 — launch-time partial failure still splits a wave.** `claim_all()` is atomic, but the per-item launch loop is not: a failed `shutil.copy` of a missing variant releases only that item (`LAUNCH FAILED`, dispatch.py:627-636) while its wave-mates are already running. tick.sh ships variants with `scp ... 2>/dev/null` (tick.sh:66) — a silent variant-ship failure is precisely the trigger. The control burns its GPU time; when it finishes, the treatment is tombstoned. Recorded honestly, but the pair is lost, and nothing pre-verifies on the host that every variant file named in the queue exists before claiming.

**SEVERITY 5 — the "which experiment runs next" answer is a committee, and the written policy is partly fictional.** The enforcement claims in CLAUDE.md do not all exist. `EXPLORE_FLOOR`: "if explore_debt is positive, the next launch goes to an unexplored axis" — `explore_debt` is computed (direction.py:426-435) and printed in a report (direction.py:533); nothing reads it. Neither queue door (queue_from_round.py, queue_quad.py) nor dispatch.py consults `agenda`'s ACTIVE_DIRECTION, `balance.py`'s ledger, or `selector.py`'s ranking — grep confirms zero imports. What actually binds at the door: lesson `blocked_values`/`blocks_keys`, `unknown_keys`, hypothesis registration, byte-identity, `blocked_reason` (dry axes), counterbalance layout. What binds at launch: gate hard checks, decision cutoff, wave integrity, `blocked_reason` again. Everything else — family choice, explore/exploit split, ranking — is advisory prose the council may ignore, and agenda.py's own comment admits a rotation "happened DE FACTO, by queueing another family's runs while the ledger still named the old direction" (agenda.py:253-258). To make it deterministic and recorded: one function, `next(results, lessons, corpus, queue) -> ordered entries`, whose output is stamped into each queue entry (`selected_by`, score, agenda state hash) and whose refusals are the *same* code the door runs. Today the dispatcher end (queue order + largest-fitting wave) is deterministic; the proposal end is not, and the tie-break is unrecorded operator judgement.

**SEVERITY 6 — divergence with the tick.sh shape.** The one-import-at-startup problem is warned about (tick.sh:44-53) but the same shape recurs elsewhere: (a) GATE_MAX_AGE is 20 min (dispatch.py:65) and the tick interval is 1200 s (tick.sh:23) — the gate file's host mtime is reset at arrival, so its age reaches the threshold at exactly the moment the next tick is due; any ssh latency or a skipped tick flaps the gate closed, a silent fail-safe stall. (b) Queue deletion propagation (tick.sh:110-124) prunes any host entry absent from the *local* queue: two workstations, or one fresh clone with a thin queue.json, silently delete each other's unlaunched work — the `if inc:` guard protects only against an *empty* local queue, not a divergent one. (c) A zombie claim makes its entry permanently un-updatable and un-deletable on the host (`launched()` includes claims, tick.sh:83-88), compounding Severity 1. (d) ACTIVE_DIRECTION.json, claims.jsonl, and lessons live only locally; the host enforces lesson blocks only via the shipped claims.py *module*, but `blocked_values` is checked at the local door, not at host launch — a lesson registered after an entry was queued never re-screens it.

**CIRCULARITY.** Two real loops, one fragile term. (1) *Hindsight credit*: `agenda.family_runs` walks results chronologically but consults `_counterbalanced_wins(results)` computed over the FULL final result set (agenda.py:151, applied at 157) — a config that eventually wins retro-marks its early runs as improvements, resetting `since_improve`/`dry` at points in the past where no such knowledge existed. Rotation triggers therefore read a quantity later runs wrote. Defensible for "rotate now?" but it means the ledger's history rewrites itself and STALE can un-fire retroactively. (2) *Blocked-family attractiveness*: a lesson's `blocks_values` removes a family's arms at the door; fewer runs keeps `gap` high, and agenda scores gap at weight 1.00 (agenda.py:230) with the spend penalty keyed to runs — a heavily lesson-blocked family looks like permanent virgin headroom, gets proposed, gets refused, forever; nothing feeds door refusals back into the score. (3) selector.py's dominant term W_RESOLVE=4.0 (selector.py:52) fires on substring matching `l["id"].split("_")[0] in blob` (selector.py:179) — for `L###_*` ids this matches any rationale mentioning "L006"; for the `lesson_*` convention used in tests/test_lessons.py the prefix degenerates to the word "lesson", which would light the +4.0 for essentially every hypothesis. A council that writes a lesson and then a hypothesis citing it manufactures the top rank — the loop verdict→lesson→selector-boost is one prose mention wide. Note `direction.axis_state` closure is also an absorbing ratchet: a closed axis reopens only via an improving run touching it, but non-best values on closed axes are refused (direction.py:379-424), so only a `holds_best` mechanism-side improvement can reopen it — by construction, mostly one-way.

**UNTESTED.** tests/ covers rotation triggers (test_rotation.py), wave grouping/claiming/tombstoning of the extracted `runnable`→`claim_all` slice (test_wave_launch.py:16-24 — note it excises exactly dispatch.py:134-324, so everything below `def release` is out of scope), lesson binding, CoE, and the round→queue seam (test_pipeline.py). **No test exists for**: `verdict.py` at all — the stage with the worst silent-drop history (odd member counts, dropped quads, VOID exclusion, same-GPU re-pairing) has zero regression tests; the tick.sh queue merge (PYMERGE heredoc: update-in-place, deletion propagation, the `launched()` guard whose pathing bug "had never once fired"); dispatch.py's `recover_orphans`/`adopt_running`/`release_stranded_claims`/`parse`/co-tenancy/quarantine/launch-failure paths; `selector.py`; `balance.py`; `gate.decision_cutoff`; `queue_quad.py`'s layouts.

**WHERE THE PIPELINE IS SOUND.** The door (queue_from_round.py) is genuinely strong: build-now variant verification, byte-identity refusal, value-level lesson blocks, hypothesis-linkage carried onto the persisted entry (the L026 fix is visible at queue_from_round.py:118-127), and queue_quad.py now runs the same checks (its own comment: "a second entrance with no lock on it is... the way in"). Claim-or-release is correct for the claim step; the cutoff/held/split/tombstone interaction encodes L022/L023 correctly for the cutoff case; wave sizing from the queue rather than the unclaimed remnant closes the W03a split; `wave_sizes`' NameError fallback keeps tests honest; results are append-only JSON with `ok:false` + `invalid_reason` rather than deletion, so losses that ARE detected stay visible; and `council._admissible` closing the "valid round, nothing runnable" seam is the right shape — validation and the door now share code instead of drifting apart.

## reproducibility (repro-1)

**Bottom line.** The benchmark contract is excellently reproducible; the campaign's *evidence* is not cloneable at all; and the analysis rules were demonstrably rewritten while the data flowed. A stranger can rebuild the apparatus but cannot check a single number in the paper.

### 1. Committed vs claimed: the clone test fails, decisively

The repo commits 85 files; `runs/` (all 138 result records, 552KB in `runs/sweep/results/`) is gitignored. Locally, `python3 tools/coe.py registry` builds 1444 citable values from 138 records and the audit reports INTACT. I git-cloned the repo into scratch and re-ran it there:

- registry: **"0 citable values from 0 result record(s)"** — empty by design.
- `coe.py` audit: **E1 fails with 706 problems** (every claim in `lit/claims.jsonl` cites a snapshot in gitignored `lit/sources/`; worse, the sha256 digests live in gitignored `lit/index.json`, so even re-fetching cannot verify the *original* bytes — tamper evidence is gone). **E5 fails with 10 problems**, including `papers/2026-08-19_three_levers_and_an_instrument.md`: **117 numbers with no registry entry** — i.e. every quantitative claim in the paper, including the headline 0.990345 → 0.986956 result, is uncheckable from a clone.

So the gitignore comment ("the transferable science lives in lit/") is wrong on its own terms: the campaign's own audit tool defines `runs/sweep/results/*.json` as the *sole* numeric evidence, and that evidence is untracked. These 138 JSONs are small, append-only records — they are **evidence, not machine state** — while `runs/*.log`, queue, health snapshots genuinely are machine state. Note also that all 138 result files carry an identical mtime (2026-08-19 05:16), meaning primary records were rewritten in place (a `metrics_backfilled` field was added); with the files untracked there is no version history of that rewrite. **Recommendation: track `runs/sweep/results/` (or ship it as a hashed release asset), commit the digest entries of `lit/index.json` for cited sources, and keep only queue/logs/health ignored.** Without that, `coe.py` INTACT is a statement about one laptop, not about the repository.

### 2. Frozen-ness: the external review's characterisation is substantially fair

The whole campaign is ~2 days old (init 08-17 05:55; first result record started 08-18 05:18; last runs 08-19 ~02:00; last commit 08-19 05:15). Of 28 commits, **21 modify policy tools** (verdict, direction, agenda, selector, gate, coe, balance, queue_from_round, make_variant, council), and **20 of those 21 post-date the first result records** — plus, right now, `tools/gate.py`, `tools/council.py` and `lit/lessons.jsonl` sit *uncommitted-modified* in the working tree. Concentration: `tools/verdict.py` (the adoption/significance judge) was edited **8 times in 8.5 hours** (20:20 → 04:26) while runs were landing; `tools/direction.py` (axis-closing) 7 times; `tools/queue_from_round.py` (candidate gating) 5 times. Specific outcome-adjacent edits: `ba02642` "Correct the significance basis of the precond win" (significance rule changed after the win was measured); `eeabd2e` "The improvement test could not see a counterbalanced win" (adoption criterion changed after it missed a win); `cc81eef` (verdict data-pooling rule changed after a pooled verdict looked wrong); `3d9185e` "Every threshold in the campaign was a constant that only held at n=4" (the noise/resolution model re-derived mid-campaign); `c955dce` "the audit rule laundered sign flips"; and lesson L043 "the seed gate was a pocket veto" (a scoring gate removed after it blocked launches). The results therefore describe a **sequence of at least ~8 distinct verdict regimes**, exactly as the review says.

Mitigations, honestly stated: every change is a separate, well-motivated commit; several pre-fix rules were provably *wrong* independent of outcome (an improvement test blind to counterbalanced wins is a bug, not a tuning); and because the raw per-run `val_bpb` records were never edited, the final ruleset **can** be re-run over all 138 records. But nothing shows that was done — the paper's verdicts were produced under whichever ruleset was live at each round. Fair label until re-analysis: **baseline development data**. The raw measurements are trustworthy; the verdict/significance/axis-closure layer is ruleset-version-dependent and unversioned per result.

### 3. Packaging and CI: broken and absent

`pyproject.toml` names the project `simplify-autoresearch-v2` (directory is v3), declares `readme = "README.md"` — **no README exists** — and exposes `autoresearch = "autoresearch.cli:main"` with `packages = ["autoresearch"]` — **no such package exists**; a `pip install` / `hatch build` fails outright. There is **no CI** (no `.github/`, no workflow files). `[tool.pytest.ini_options]` is configured, but the six files in `tests/` define **zero `def test_` functions** — `pytest` collects nothing; they are run-as-scripts with `print(PASS/FAIL)` and `sys.exit`. Two use `TemporaryDirectory` properly (`test_rotation`, `test_wave_launch`), but `test_lessons.py` **mutates live state**: it writes a real round into `rounds/`, executes the live `tools/queue_from_round.py` against the live `runs/sweep/queue.json` (save/restore that leaks on mid-test crash), and `test_chain_of_evidence.py` writes fixture files into the live `lit/sources/` tree. Redeeming detail: `coe.py --json` exits 1 on a broken chain, so it is CI-ready — CI on a clean checkout would have caught the clone failure on day one.

### 4. Agent decision provenance: labels, not provenance

Rounds and critiques carry free-text agent ids (`explorer-r1`, `fable-ev-4`); `tools/council.py` validates only that role sections exist, ids are distinct, and word floors are met. The critique *template* names `claude-fable-5`, but no artifact records per-agent: model id and version actually used, the full dispatched prompt (the committed template is interpolated with un-snapshotted live state — registry, lessons, agenda at dispatch time), sampling settings/seed, token/time budgets, which files each agent read, or transcripts. The rounds are unusually rich in *checkable content* (train.py line numbers, claim ids, arithmetic), so a stranger can verify the stated reasoning — but cannot re-generate it or distinguish agent output from operator paraphrase ("the panel's text verbatim" is asserted, not evidenced). Reproducing WHY an experiment was chosen requires: prompt digest + state snapshot hash + model/version + settings per agent, stored in each round header.

## synthesis (proj-syn-1)

**1. What this system is actually good at.** Three properties, stated precisely. First, the verdict layer is genuinely strong: `tools/verdict.py` and the measurement functions in `tools/direction.py` measure their own instrument rather than assuming one (noise band from concurrent controls only, `resolution_at(n)` instead of an n=4 constant, device model instead of core-block folklore), they exclude VOID cells and then *announce the design degradation that exclusion causes*, and when the conservative and paired thresholds disagree they say so instead of picking the flattering one. Second, the failure defaults point the right way almost everywhere: `is_platform()` fails safe on any unrecognised key, an unmeasured band means no axis may close, a stale gate verdict stops the dispatcher, tombstoned wave-remnants become invalid results that demand a lesson rather than deletions, and `claim_all()`/`release()`/`adopt_running()` make dispatcher restart safe. Third — and rarest — the codebase is its own audit trail: nearly every guard carries the specific observed failure that necessitated it (the `[A-Za-z]` metric-parser fix citing L015, the lexicographic-sort sign flip in `slot_bias`, the odd-member-wave orphan note), and `tests/test_policy_defects.py` / `test_rotation.py` are executable proofs of policy, not unit trivia. E5's derivation checker in `coe.py`, after two audits defeated it, now verifies signed arithmetic and bounds summary statistics — that is real hardening.

**2. The single biggest structural weakness of the code: there is no shared analysis layer, so every policy module re-derives statistics from raw result JSON with slightly different filters, and the divergences are where the defects live.** `_device_means()` is copy-pasted verbatim into `selector.py` and `balance.py`; `agenda._counterbalanced_wins()` derives a third device correction of its own; the `final_epoch == 2.0` filter appears in some derivations and not others; family attribution exists four times (`selector._families`, `agenda.families_of`, `direction.FAMILIES`/`MECHANISM_FAMILIES`, and `lit.ALL_FAMILIES` as a fourth registry). The campaign's own lesson history is the argument: the selector attributing every experiment to four unrelated families, `precond` runs invisible to DRY/STALE/HARD-CAP because `MECHANISM_FAMILIES` used a key `lit.ALL_FAMILIES` did not contain, `balance.classify` reporting 62% then 50% exploitation for a true figure near zero, the verdict pooling a repaired mechanism with its broken predecessor — every one is two re-derivations of the same quantity disagreeing. The growth pattern makes it worse: each fix is an exemption bolted onto one copy (`holds_best`, `_exploring`, counterbalanced-win credit, cutoff-frozen wave denominators), so the copies drift further apart with every repair. The fix is one `tools/effects.py` owning load → validity filter → device correction → family attribution → pairing, imported by selector, balance, agenda, verdict, and direction, plus a startup assertion that every family key in `direction.py` exists in `lit.ALL_FAMILIES`.

**3. The selector gap is not closed.** The import graph is unambiguous: nothing imports `selector.py`, nothing reads its output, and no queue entry records a rank. Of the two reviews' three recommendations, (a) exists but is advisory, (b) the controlled benchmark does not exist in any form, and (c) was violated the same day it was made — the `project` critique cadence added to `council.SPECS` is a new two-hour process gate, whatever its non-freezing status. "Closed" looks like this, concretely: `queue_from_round.py` runs every admitted entry through `selector.score()`, orders the queue by it, and stamps `selector_rank` and `selector_terms` into each entry so the choice is recorded and reproducible; the round-synthesis prompt requires the ranking pasted into the artifact; `dispatch.next_batch()` breaks ties between intact waves by recorded rank instead of queue order. The full four-arm ablation benchmark is unaffordable at this GPU budget — say so and substitute the cheap version: with ranks recorded on every result, after ~30 treatments compute whether rank predicted realized device-corrected effect. That retrospective calibration is the benchmark this campaign can actually buy, and it also supplies the first data that could ever justify fitting the selector's stated-not-fitted weights.

**4. Complexity budget: yes, shrink, and here is the deletion list.** `tools/sweep_chart.py` and `tools/make_chart.py` (48KB combined) read `.autoresearch/records/`, which does not exist in this tree, and `sweep_chart` hardcodes a previous campaign's PROBES plus a duplicate of PLATFORM — delete both; a chart for *this* campaign should be a fresh 100-line script over `runs/sweep/results/`. `tools/read_arxiv.py` writes to `runs/science/sources/` (retired harness path, also nonexistent) and is superseded by `lit.py screen/fetch` — delete. `tools/bootstrap_controls.py` is a one-shot seeder whose job is done (138 results on disk) and whose function `queue_controls.py` now owns with better guards — delete. `tools/observables.py` is imported by nothing and the operator directive already made it non-binding; fold any still-useful `emits` lists into the hypothesis records that actually govern activation, then delete. `tools/balance.py` is a fourth explore/exploit accounting (after `direction.explore_debt`, the dry rules, and agenda rotation), imported by nothing and absent from the CLAUDE.md loop — merge its EXPLOIT_FLOOR ledger into `direction.report()` and delete the module. That is five of ~15 modules gone with zero behavior change to anything that launches. The six same-day loosenings are the argument for shrinking: each one kept the enforcement scaffolding and added an exemption, so binding force fell while audited surface grew — the worst ratio available. Do **not** delete `selector.py`; it is the one module the external reviews asked for, and it is the only one pointing at the acknowledged weakness.

**5. Priorities.** Before more GPU time: (1) wire the selector in as specified above — arm choice is the admitted weakest link and GPU minutes are the scarce resource, so an unconsumed ranking is paying the selector's complexity cost for none of its benefit; (2) the family-registry unification assertion (one test, prevents the whole precond-invisibility class); (3) extract `effects.py`, or minimally move `_device_means` and the epoch filter into `direction.py` and import them in the two modules that pasted them; (4) delete the five dead modules — fifteen minutes, and it shrinks what the two-hourly project critique must re-audit. Can wait: the dispatcher auto-restart on module-digest change (tick.sh already ships, verifies, and warns; a manual restart at the next idle gap is tolerable), any refactor of the working E5 derivation engine, converting the exit-on-first-failure test scripts to pytest collection, and the four-arm process benchmark, which should be replaced by the retrospective rank-calibration above rather than scheduled.
